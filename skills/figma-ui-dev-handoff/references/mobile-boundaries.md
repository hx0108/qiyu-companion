# 移动端实现边界

不要把主设计尺寸等同于唯一支持尺寸。根据产品目标设备逐项给出规则和验收样例。

## 视口与安全区

- 记录主 Frame 宽高及设备基准。
- 至少定义相邻窄宽、小屏和长屏；若产品有明确目标，使用其真实尺寸。
- 顶部内容避开状态栏、刘海和动态岛；底部操作避开 Home Indicator。
- 固定导航、输入区和弹层分别说明是否包含安全区内边距。

## 键盘与输入

- 说明键盘升起后页面 resize、pan 或 overlay 策略。
- 输入区保持可见；消息列表可用高度随键盘变化。
- 定义多行输入最大高度、发送键、换行、语音输入和草稿保留。
- Toast、核验结果或异步回调不得无故清空未发送内容。

## 小屏、长屏和大字体

- 窄屏不允许核心操作横向溢出；必要时按钮堆叠。
- 长屏不通过固定空白把主要操作推离可达区域。
- 系统大字体下避免固定高度裁切；定义最大字号策略和滚动兜底。
- 长中文、英文、数字、URL 和不可断文本分别验证。

## 横屏

明确选择：支持并给出布局、锁定竖屏，或允许横屏但显示受限提示。不得留为默认未知行为。

## 图片与视频

- 为头像、卡片、情境图和全屏媒体分别定义比例。
- 写明 `cover`、`contain`、焦点位置、圆角、占位、失败和敏感内容遮罩。
- 不能用拉伸填满容器。

## Bottom Sheet 与 Dialog

- Bottom Sheet 最大高度需考虑安全区和键盘，内容超过时内部滚动。
- 定义关闭手势、遮罩点击、系统返回键和未保存编辑保护。
- 高风险确认不能因滑动误触关闭。

## 消息列表

- 定义首次进入、回到底部、加载历史、收到新消息和发送失败后的滚动行为。
- 用户阅读历史时，不强制跳到底部；提供新消息锚点。
- 媒体加载导致高度变化时保持视觉锚点。
- 删除、撤回或审核屏蔽后保持可解释的位置反馈。

## 主题

- 明确日夜模式是跟随系统、用户设置还是业务场景；给出优先级和切换时机。
- 业务动作不能隐式改变全局主题，除非产品合同明确要求。
- 切换后保证文字、图标、媒体遮罩、系统提醒和输入区对比度。

## 无障碍与反馈

- 触控目标、焦点顺序、屏幕阅读器名称、动态内容播报和减少动态效果。
- 颜色不是唯一状态信号。
- Loading、成功、失败和重试都提供文本反馈。
