# 栖语 M1 开发基线（内部可验收切片）

状态：2026-09-03 起草；适用范围仅为本地开发/合成数据验收，不构成外部封测或公开上线批准。

## 1. 本轮目标

从现有可点击演示过渡到一条可由服务端事实驱动的最小闭环：

`必要告知 -> 年龄准入 -> 单角色创建 -> 文字互动 -> 候选记忆 -> 用户确认 -> 关系资产 -> 删除后在线召回撤销`

这对应 PRD 的 M1「文字与人格/记忆主链、年龄核验适配器、30/90 天 TTL 与删除编排原型」。默认使用合成开发账户和确定性 Mock 回复；后续可在本地开发进程显式启用 Qwen3.8-Flash。不能把开发年龄判断或本地存储称作第三方核验或生产持久化；Qwen 开发外呼也不构成生产批准。

## 2. 可实现范围与排除项

本轮落地：

- 版本化的必要告知展示回执；回执缺失时普通互动返回 `428 REQUIRED_NOTICE_PENDING`。
- 年龄声明的确定性开发策略：明确未满 18 岁为 `AGE_DENIED_MINOR`；有效成人声明为 `AGE_PASS`；出生日期变更、无效声明或申诉为 `AGE_REVIEW`。非 `AGE_PASS` 时聊天、记忆与媒体写入均被服务端拒绝；`AGE_REVIEW` 仅表示需要后续合规最小年龄断言，不是核验通过。
- 每账户仅一个活跃角色；服务端从鉴权主体取得账户范围，任何读写都带 `account_id + character_id` 约束。
- 文字对话的安全受控开发实现：默认由可替换的 Mock Adapter 生成并标明 `provider=mock`；可显式启用 Qwen3.8-Flash 本地开发 Adapter，服务端必须写入实际 `provider` 与 `model_version`，且不得持久化推理字段。
- 在任何模型调用前执行固定开发安全集：明确自伤自杀、重大财产风险进入 `R2_CRISIS` 并暂停普通角色互动；高困扰进入 `R1_SUPPORT`；依赖表达使用固定提醒。安全响应标为 `provider=safety-policy`、不创建候选记忆，且不是生产危机服务或 H3 通过证据。
- `CANDIDATE -> CONFIRMED | CONFIRMED_EDITED | REJECTED | EXPIRED`，仅确认后的 `ACTIVE` 关系资产可被召回；删除资产后必须立即不可召回。
- 删除任务的第一个正确性界限：创建时增加 `revocation_epoch`、立刻移出在线查询，并返回真实的开发任务状态；不得以动画或 Toast 伪造完成。
- 面向原型主路径的本地 Web 壳，保留 AI 标识、系统提示、393px 移动端基线及日/夜主题；所有状态以 API 返回为准。

本轮明确不接入：真实身份/年龄供应商、紧急联系人外呼、图片供应商、支付、自动续费、主动消息、真实危机联络、真实生产数据和外部发布。Qwen、腾讯云文本审核与腾讯云 TTS 仅存在本地开发的显式外呼路径；TTS 只处理已审核助手文字、写入开发私有媒体库并支持在线撤销，不能视为生产接入或验收通过。其余能力只能保留为默认关闭的 Adapter/Feature Flag 边界，不能提供可误用的假成功入口。

## 3. 架构决定

先交付无外部下载依赖、可用 Node 22 直接启动的本地纵向切片：

- `apps/api`：原生 Node HTTP API；领域模块分别实现 AccessPolicy、Notice、Age、Character、Conversation、Memory、Deletion。所有不可逆状态变化由确定性服务完成。
- `apps/web`：同一 API 服务托管的静态开发前端；只通过 `/api/v1` 调用，不自行决定年龄、记忆、删除或额度成功状态。
- `contracts/openapi.yaml`：本切片接口的机器可读合同；错误结构、幂等键与状态枚举必须与实现及测试一致。
- `test`：使用 `node:test`，且只生成合成数据。生产替换目标为技术设计指定的 PostgreSQL/pgvector、Redis、Outbox 与隔离 Worker；本地存储实现不得被接到生产配置。

为确保开发期间仍有账户隔离，开发环境使用固定、明确标识的合成 Bearer token 映射到账户；任何缺少或未知 token 的请求返回 `401`。这不是生产鉴权方案。

## 4. 首批验收条件

1. 未展示完必要告知不能创建普通角色消息，返回 `428`。
2. 未成年人、年龄复核中、未鉴权账户不能创建会话或发送消息；告知/申诉/数据权利入口不被同一策略误阻断。
3. 默认 Mock 或显式 Qwen 对话只能创建候选；候选被拒绝或未确认时，关系资产/召回接口为空。
4. 用户确认或编辑确认后才出现 `ACTIVE` 资产；不同合成账户、不同角色永不互见。
5. 删除确认资产后，在线资产和召回结果立即为空；响应包含任务与撤销纪元，不能假称物理生产清理已完成。
6. 同一幂等键配合相同载荷重放原结果；同键不同载荷返回 `409 IDEMPOTENCY_CONFLICT`。
7. `node --test` 覆盖以上路径；本地浏览器可跑通准入、聊天、确认记忆、删除四步。
