# UI 与开发交付包

## 目标

把视觉 Demo 整理为可编辑、可追踪、可实现和可验收的交付物。静态页面用于确认结果，组件规范用于复用，状态合同用于行为，追踪矩阵用于连接接口和埋点。

## 必须交付

### 1. 静态页面与关键状态

与 `screen-manifest.json` 一致，覆盖主流程以及范围内的加载、空、失败、权限、额度、审核、安全、删除、降级、日夜主题和系统大字体等状态。对尚未设计的状态明确标注缺口，不用相近页面代替。

### 2. Design Tokens

至少定义：

- 品牌色、背景、文字、描边和语义色。
- 字体族、字号、字重、行高和字距。
- 间距、栅格、圆角、阴影、透明度和层级。
- 图标尺寸、触控区域和媒体比例。
- 动效时长与缓动；静态导入版可以不执行动效，但规格必须说明。
- 日间、夜间、高对比度或其他已确认主题。
- 安全区和主要视口变量。

优先同时输出 `tokens.json` 和可供前端使用的 `tokens.css`。不要把未确认的数值标为最终 Token。

### 3. 组件规范

每个正式组件记录：

- `component_id` 与中文名称。
- 用途、结构、插槽和内容规则。
- 尺寸、约束、变体和组合关系。
- Default、Pressed、Focused、Disabled、Loading、Empty、Error 等适用状态。
- 交互、反馈、动效和无障碍要求。
- 长文案、系统大字体、小屏和夜间模式边界。
- 对应接口字段、事件和埋点。
- 不应成为组件的页面特例。

组件中文名遵循 `组件｜变体｜状态`；代码侧名称另列，不混用。

### 4. 状态合同

一个状态合同至少包含：

- 稳定 `state_id` 与中文状态名。
- 所属 Screen、入口条件和前置权限。
- 展示数据和来源。
- 用户动作、系统动作和下一状态。
- Loading、超时、失败、重试、幂等和取消。
- 是否持久化、数据保留与删除联动。
- 安全、审核、额度和降级规则。
- 接口、埋点和验收条件。

模型生成内容只能作为数据候选；权限、状态、额度、安全门禁和删除等结果由确定性合同控制。

### 5. 页面—状态—接口—埋点对照表

每个已交付 Screen 至少占一行，字段至少包括：

| Screen ID | 中文 Frame 名 | 状态 ID | 进入条件 | 接口 | 关键字段 | 用户操作 | 下一状态 | 埋点 | 验收条件 |
|---|---|---|---|---|---|---|---|---|---|

不存在真实接口时写 `待定义`，不得编造 URL 或声称已接入。接口存在但实现未验证时写明证据边界。

### 6. 实现边界

移动端项目按 [mobile-boundaries.md](mobile-boundaries.md) 逐项定义。非移动端则以相同思路补齐断点、输入、滚动、媒体和无障碍边界。

### 7. 联合验收清单

按责任方拆分：产品、UI、客户端、服务端、数据/埋点、测试、合规和无障碍。每项写明验收证据，不以“已完成”代替可观察结果。

## 推荐目录

```text
handoff/
├── static/
├── specs/
├── tokens/
├── assets/
├── prototype/
├── scripts/
└── README.md
```

这是项目交付目录，可以包含 README；Skill 自身不需要另建 README。

## 交付边界

- HTML 元素看似可点击，不等于接口已实现。
- 静态页面通过结构校验，不等于浏览器视觉 QA 或 Figma 导入通过。
- Figma Frame 已存在，不等于组件、Variables、Auto Layout 或 Prototype 连线完成。
- 对照表已填写，不等于后端接口或埋点已上线。
- 联合验收清单已生成，不等于联合验收已执行。
